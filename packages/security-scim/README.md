# @arkenivajs/security-scim

SCIM 2.0 User/Group provisioning through native `scimmy@1.3.5` schemas, filters and PATCH. `createScimService(settings)` exposes the typed service; `scimPlugin(settings)` registers `/scim/v2` on the existing HTTP, HTTPS or HTTP/2 API server. Bulk requests and custom schema extensions are unsupported.

Standalone settings accept `auth`, `authority`, `environment`, `maxPageSize` and `maxFilterDepth`. Missing authentication or independent authorization denies provisioning. The default environment is `production`; test-only providers and authorities are rejected outside `test`. Register providers before the first request. Plugin settings require User/Group providers, trusted authority, capabilities, page/filter limits, request byte limit and concurrency limit. Authentication, readiness, logging, optional telemetry and optional technical metering retain their existing owners.

Every operation verifies the bearer and requires an actual verifier-owned tenant context. A manually constructed `ScimHttpRequest.auth` is insufficient: it must match the newly verified issuer, subject and tenant. Exact scopes are `scim:users:read`, `scim:users:write`, `scim:groups:read` and `scim:groups:write`. Discovery requires a read scope. Independent authority actions are `scim.users.read`, `scim.users.write`, `scim.groups.read`, `scim.groups.write` and `scim.discovery`.

`ScimProvider` must bind ownership, immutable external identity mappings, uniqueness, idempotent retries and version predicates to the actual shared transaction. Adapter prechecks do not replace atomic provider `ifMatch` checks. Privileged membership requires explicit application policy. The [PostgreSQL reference](../../examples/postgres/scim.md) demonstrates these boundaries and independent-process races. There is no production memory fallback.

GET supports one-based `startIndex`, bounded `count`, native filtering and optional sorting. Provider pages are already paginated and cannot be silently truncated or paged twice. Responses use SCIM JSON, sanitized errors and validated ETags. Mutation timeout, cancellation or invalid acknowledgement can mean an unknown outcome; reconcile using the provider's immutable identity mapping before retrying.

Defaults bound JSON to 256 KiB, depth 16 and 8192 nodes; page size to 100 (maximum 1000); filter depth to eight (maximum 16); filter text to 4096 bytes, eight disjunctions and 32 logical joins; and PATCH to 100 operations. The plugin permits request limits up to 256 KiB and physical concurrency from 1 to 128. Standalone concurrency is eight. Operation deadlines default to five seconds and cannot exceed 30 seconds. Cancellation retains capacity until actual provider work settles; shutdown rejects new work and bounds drain time.

The reviewed compatibility diff fixes pathless replacement, empty pages and schema-aware comparisons in the pinned native ESM distribution. Attribute `caseExact` and date metadata govern comparisons without rewriting stored values. Generic SDK comparisons without schema context retain their original behavior. See [third-party notices](THIRD_PARTY_NOTICES.md).

Telemetry records operation counts, duration, active physical calls and compact JSON payload size with closed operation/resource/outcome/direction labels. JSON size is a derived representation size, not network traffic. Existing technical metering receives an authenticated operation scope and elapsed time. Diagnostics omit bearer tokens, tenant/user identifiers, profiles, filters, patches and provider errors. Diagnostic failures cannot repeat business work.

Run `pnpm --filter @arkenivajs/security-scim build` and `pnpm --filter @arkenivajs/security-scim test:unit`. The [public consumer](../../examples/scim/README.md) exercises real signed bearer tokens and native HTTP/TLS transports. Local fixtures do not establish external identity-provider certification or a production deployment assessment.
