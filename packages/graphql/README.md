# @arkenivajs/graphql

Optional GraphQL query and mutation integration on the existing Fastify HTTP, HTTPS or secure HTTP/2 listener. Register `graphqlPlugin({ schema, resolvers, security })` at application construction, alongside the API adapter. `GRAPHQL_CAPABILITY` resolves an administrative service exposing only `stats()`, `health()` and `schemaSdl()`.

The implementation uses Mercurius 16.12.1 and GraphQL 16.14.2 over Fastify 5.12.7. Core and REST-only applications do not import this package. The plugin requires explicit application HTTP configuration and, by default, an authentication provider. SDL, field mappings and startup declarations are validated before listener activation. It never creates another listener.

Application HTTP configuration owns TLS certificates and the `http2` switch. Secure HTTP/2 negotiates `h2` and preserves HTTP/1.1 fallback on the same endpoint. Multiplexed streams retain independent verified tenant contexts; resetting one stream cancels its resolver signal without closing other streams. Graceful application shutdown waits for accepted work before closing the listener.

Anonymous policy requires an explicit list of public `Query.<field>` roots and a reason. Every resolved field needs an application authorization decision; a tenant argument is never authentication evidence. Batch results retain order, length and null entries. Subscription delivery requires verified tenant provenance and a shared production backend, with bounded transport and periodic revalidation.

POST accepts one JSON operation. GET queries require explicit opt-in; mutations through GET are rejected. Documents, variables, depth, expanded aliases, list complexity, resolved fields, returned collections, elapsed time and encoded results have finite limits. Field policy must return exactly `true` before explicit resolution or default property access. Application services still own row-level authorization and tenant filtering.

Result encoding uses Node's JSON serializer with incremental byte accounting. It rejects oversized strings before allocating their escaped representation and stops once the total response budget is exceeded. Output must be JSON-compatible; cycles, bigint and unsupported object wrappers fail safely. The total operation deadline is checked again after encoding, including when a mutation has already taken effect.

Cookie-bearing and cross-site browser requests are rejected. No cookie authentication is enabled. A declared anonymous operation never accepts a forged bearer assertion as a public fallback. Error responses omit exception causes, documents, variables and backend diagnostics. Timeout never implies rollback: an admitted mutation may still commit, and the adapter retains ownership until its underlying work settles. There are at most 128 physically outstanding operations per instance; new admissions are rejected while that capacity is occupied.

Loaders use Mercurius's native scheduler. Each batch contains at most `maxBatchSize` requests, default 100 and maximum 1000. The ordered result must be an array with exactly the same length, including null entries. Per-item failures become sanitized field errors. Parent objects remain opaque to cache-key construction, so private getters are not evaluated as a side effect of batching.

Result caches exist only inside one authenticated request and use parent identity and coerced arguments. Authorization still precedes every lookup, including a cache hit. `cache: false` preserves distinct alias requests. Caches are invalidated between serial mutation root fields. Application loaders must apply the verified tenant and row-level policy to their database reads; batching does not authorize records.

Schema introspection is disabled by default. `introspection: 'authenticated'` requires a trusted authentication provider and an explicit `introspectionScope`; every introspection request must prove that scope. Metadata fields, including `__typename`, also pass ordinary field authorization with their actual parent and response path. Large administrative introspection queries remain subject to the configured budgets; enabling introspection never relaxes limits automatically.

The upstream GraphQL package shares its built-in metadata definitions across schemas. Their resolver guards dispatch only through an internal map of owned request contexts, preserving unrelated native schemas. Separate framework applications retain separate identity and field policies. Replacing an installed guard causes owned requests to fail closed before executing fields.

`developerIDE: true` enables GraphiQL at `<path>/ide` only in explicit development or test environments. Production startup rejects this option. Page and asset requests require a verified bearer identity and tenant; configured scopes and assurance still apply. When administrative introspection is enabled, its scope is also required. The hosting environment must provide Authorization headers for page and asset requests; credentials are never embedded in HTML or URLs.

IDE assets and language workers are bundled locally from pinned dependencies. The browser makes no CDN requests, sends GraphQL operations as same-origin JSON POST with cookies omitted, and discards persistent query/header storage. Resource budgets remain in force for introspection; enabling the IDE never raises them automatically. Bundled upstream license notices accompany the package. Browser builds use the WebAssembly bundler and require no native compiler or installation hooks.

IDE startup reads only its fixed local build directory. The manifest is limited to 1 MiB, names to 128 characters, each regular asset to 32 MiB and the aggregate to 64 MiB. File size is verified before fixed buffer allocation; extra or truncated bytes, links, directories and hash mismatches reject startup. Artifact filenames and filesystem errors are not returned as application error details.

The declaration-only Monaco compatibility correction uses its public `KeyCode`, `KeyMod`, `Uri` and `Range` types while preserving the upstream SSR-safe JavaScript imports. The selected stable React compiler runtime has a byte-identical JavaScript artifact to the replaced prerelease helper. Core and REST imports never initialize React or the IDE.

When a telemetry provider is installed, the adapter exports `arkenivajs.graphql.requests`, `operation.duration`, `operation.complexity`, `loader.batch_size` and `denied` under the same prefix. Duration is in seconds; complexity is the derived policy work estimate. Request counts include parser and authorization failures. Resolver errors and timeouts remain distinct from policy denials. Field durations are enabled only in `detailed` telemetry mode, grouped into business or metadata fields.

Metric labels use fixed operation kinds, outcomes and rejection categories. Documents, client-selected operation names, variables, arguments, tenant identifiers and tokens never become labels. Loader observations count actual scheduled batch items. Existing HTTP duration and body-byte observations stay in the API adapter; GraphQL does not repeat network bytes or treat overlapping durations as CPU consumption. Diagnostic failures never repeat application work or grant access.

Subscriptions export `arkenivajs.graphql.active_subscriptions`, `subscription.queued` and `subscription.events`. The active gauge counts physical WebSocket connections; queue gauges distinguish retained admission credits from pending native writes. Their labels use only fixed subscription and queue classes. Delivery means a successful native write callback, rather than proof of client processing. An observed source event abandoned before that boundary counts as a drop. Application-owned broker publishing is not automatically counted as a GraphQL publish observation; its provider owns that measurement. Payloads and client-selected operation IDs never enter metric labels.

The subscription adapter propagates the bounded W3C carrier from the upgrade request into an `http.server.request` span covering connection authentication. Separate normalized `graphql.subscription` child spans cover source acquisition and each event's processing through physical scope retirement. The authentication span does not measure the full socket lifetime or HTTP upgrade latency. Native resolver callbacks retain their owning event's trace context; idle waiting between source events is excluded from event processing spans. Documents, variables, operation names and credentials are excluded from trace attributes.

Tracing retains the framework's `http.server.request` server span and W3C `traceparent`/`tracestate` extraction. Operation spans use fixed names such as `graphql.query` and `graphql.mutation`, parented to that request. The trace carrier is bounded and never establishes identity. Malformed JSON still produces an HTTP span; IDE failures are not labeled as GraphQL operations. Trace providers cannot repeat business work even if context setup throws or invokes its continuation more than once.

Include the configured endpoint in the telemetry plugin's finite route catalog, for example `labelValues: { route: ['/graphql'] }`, to enable existing HTTP route measurements and span attributes. This administrative catalog is not populated from request URLs.

With metering enabled, verified authenticated requests create exactly one HTTP usage parent and one GraphQL execution child. Resolver and downstream service work inherits the child scope. Anonymous public queries create no synthetic tenant or tenant event. HTTP request/response byte totals belong only to the parent; the child records `graphql.operations`, successful `graphql.resolved_fields`, actual `graphql.loader_batches` and `graphql.loader_items`.

The input byte count comes from the received JSON buffer, rather than a claimed Content-Length or re-encoded variables. Output bytes are measured from the serialized response. Denied fields do not count as successful resolutions. Events retain verified tenant provenance, request identity and `parentOperationId`; query names, documents, variables, token values and payload contents are not copied into them.

The HTTP event ends with the response. If physical work remains after timeout, its quality reports unobserved downstream work; the GraphQL child stays owned until that work settles and reports an unknown outcome. A timeout does not prove mutation rollback. Meter capacity/export diagnostics remain in the existing bounded meter; accounting failures never repeat business work or bypass field authorization. A meter rejection of tenant provenance fails authentication closed.

Subscription activation currently requires direct HTTPS and `service.environment: 'test'`. Other environments reject startup. Clients use exactly `graphql-transport-ws` and supply `{ authorization: 'Bearer ...' }` in `connection_init`; URL credentials, cookies and unlisted browser origins are rejected. Normal HTTP operations retain their existing policies on the same endpoint, including secure HTTP/2 with HTTP/1.1 fallback. Realtime routes share one native WebSocket dispatcher.

Every subscription start and event rechecks the verified identity and field policy. Idle connections are revalidated at the configured interval. Connection and operation reservations remain charged until physical work retires; cancellation does not free a late iterator prematurely. Finite pending frames, socket writes, output bytes and write deadlines prevent hidden native queues from growing without bound. A failed provider retirement makes the transport unavailable for new connections.

Native protocol ping/pong liveness uses the existing `maxOperationMs` transport bound for the heartbeat interval and acknowledgement deadline. A missing pong closes its connection; repeated server pings never extend an outstanding deadline. Pong messages prove only liveness and do not replace authentication or periodic session revalidation.

The application owns the configured PubSub service and closes it after application shutdown. The GraphQL adapter owns and returns each individual subscription iterator. Providers must verify tenant provenance and producer identity independently; a client-selected topic or tenant argument grants no authority. In-process fixtures do not establish cross-pod delivery. Production shared-provider verification, distributed delivery acceptance and complete release evidence remain required before production subscription activation.
