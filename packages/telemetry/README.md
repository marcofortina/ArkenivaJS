# @arkenivajs/telemetry

`createTelemetry(options)` creates an owned SDK with the public `Telemetry` methods. `telemetryPlugin(options?)` uses root service/mode/sampling policy and provides `app.telemetry`. Register logging explicitly. Module imports start no collector, timer or listener. Each application owns independent providers and AsyncLocalStorage; initialization and shutdown never replace or disable a process-global OTel provider/context manager. Raw auto-instrumentation needs its own explicit bootstrap and must avoid measuring the same operation twice.

Options require service metadata and, for an enabled mode, a trusted collector `endpoint` origin. HTTPS uses native CA/hostname verification and Node's TLS 1.2 minimum. Plain loopback HTTP is an explicit `allowInsecureLoopback:true` development/test opt-in; it is forbidden in production. OTLP JSON goes to `/v1/traces` and `/v1/metrics`. Export timeout defaults to 5000 ms, metric interval to 10000 ms, and exporter concurrency to one. The interval must be at least the timeout. Configure collector access and retention independently; diagnostic export is best effort.

`off` allocates no provider/exporter and drops metric samples; callbacks still execute and preserve their values/errors. `minimal` exports metrics without spans. `standard` defaults to parent-based 10% root sampling; `detailed` defaults to 100%. An explicit sampling ratio is 0–1. `status()` reports the actual mode/provider state; zero-sampling spans may still carry correlation without being retained. Trace sampling never defines independent metering completeness.

`measure(name, fn, options?)` returns a Promise with the callback's original value/exception, times it using the monotonic clock and records one `arkenivajs.operation.duration` observation in seconds. `withSpan(name, fn, options?)` creates a child span when tracing is configured and always ends it in finally. Operation names are stable identifiers, 1–128 letters/digits/underscore/dot/hyphen beginning with a letter. Never insert tokens, record IDs or user input. Attributes use the same safe label policy as metrics. Span errors include only a stable error code, with no native message, stack, payload or exception event. Diagnostics dropped during completion never overwrite a completed business result.

`addCounter(name,value,attrs?)` is synchronous and requires a finite nonnegative value. `recordHistogram` and `setGauge` require finite values; gauges retain a current value per series. Reusing a name with another instrument kind rejects. The defaults bound instruments to 64, series per instrument to 128, queued spans to 2048 and active spans to 2048. Invalid samples/policy use `EK_CONFIG_INVALID`; exceeding diagnostic span bounds increments `droppedSpans` and runs the callback. Metric cardinality/instrument violations reject explicit recording; completion measurements count `droppedMetrics` instead of changing business outcomes.

Only `route`, `method`, `status_code`, `peer.service`, `db.system.name`, `db.operation.name`, `pool`, `driver`, `service`, `exporter`, `reason`, `state`, `kind`, `direction` and `operation` labels are eligible, up to eight per sample. Known methods, backend systems, direction, exporter, CPU state and bounded HTTP status codes have built-in values. Service must match this service. Other values require an explicit finite `labelValues` allowlist; operation names are admitted into a bounded measurement-name registry. Tenant, request/trace IDs, raw URL, SQL, object keys and arbitrary attributes are rejected. Each string is bounded to 128 characters. Application authors must declare route templates instead of concrete paths.

Standard duration instruments use seconds. RSS and observed body bytes use `By`; event-loop utilization uses `1`. Unknown instruments use `{operation}` for counters and `1` for histograms/gauges. Duration histograms publish `DURATION_BUCKETS_SECONDS`, from 0.0001 through 30 seconds plus the implicit overflow bucket. Backend queries calculate quantiles; the framework does not fabricate p95 gauges. CPU/RSS are process-level measurements, never exact tenant attribution. This package does not automatically collect process counters; explicitly connect the diagnostics snapshots or workload collectors.

Resource metadata includes service name/version, `deployment.environment.name`, actual process id and an owned instance UUID unless supplied. Optional trusted `workload:{namespace,pod,container,node}` adds standard Kubernetes resource names after validation. Headers never supply workload identity. `resource()` returns the immutable view; no arbitrary environment-variable dump is captured.

`withRemoteContext(headers,work)` extracts only W3C traceparent/tracestate and scopes them to this instance's async work. Invalid W3C context is ignored. Baggage and identity headers are not propagated as authorization. `traceHeaders()` and `currentTraceId()` read the scoped context; use them for outbound propagation and protected metering correlation. A downstream service must independently verify its access token and tenant entitlement.

`flush(options?)` waits for SDK buffers and in-flight exporter work within the caller deadline. Abort/timeout uses `EK_ABORTED`/`EK_TIMEOUT`; exporter rejection uses `EK_BACKEND_UNAVAILABLE`. `close(options?)` ends active diagnostic spans, stops periodic export and closes providers once; concurrent closes share completion. All new work after close uses `EK_RESOURCE_CLOSED`. A callback already running remains application-owned. `stats()` exposes local start/end, active/pending, export failure, dropped metric/span and instrument/series counts; it is not historical storage. `native()` returns the owned vendor providers and permits extensions outside adapter cardinality/redaction guarantees.

Tests use actual SDK HTTP exports to disposable receivers, test W3C parents across concurrent asynchronous scopes, resource metadata, histogram buckets, queue pressure, exporter failure and cleanup. The integration fixture runs a real digest-pinned collector with bounded resources. Receiver acknowledgments mean collector acceptance, not durable long-term storage.

Run the actual collector integration on a disposable Docker host (or inside a dedicated VM):

```sh
docker compose -f packages/telemetry/test/fixtures/compose.yaml up -d
pnpm build
ARKENIVAJS_OTLP_ENDPOINT=http://127.0.0.1:4318 ARKENIVAJS_OTLP_EVIDENCE_PATH=/tmp/collector-evidence.json pnpm test:integration:telemetry
node scripts/check-collector.mjs /tmp/collector-evidence.json --docker
docker compose -f packages/telemetry/test/fixtures/compose.yaml down
```

For a remote VM, forward its collector port to loopback, select that endpoint and retain the evidence outside the checkout. Capture `docker logs` inside the VM to an external file, then pass that file instead of `--docker` to the checker. The checker requires the exact emitted trace id, instance id, operation, metric and resource keys in the collector's output; it fails if any are missing. Debug output is for disposable fixtures only, with no real credentials or tenant data. Shut down the fixture even after a failed test.

HTTP adapters accept the abstract telemetry port. Declare explicit plugin dependencies and finite route labels; they create one server span and one logical outbound span per hop. Reserved HTTP server/client and database client operations carry the corresponding native SERVER/CLIENT span kind; other operations remain INTERNAL. Response bytes use `server.response`/`client.response` roles and exclude request bodies and wire overhead. `setGauge('http.server.active_requests', value, attrs)` maintains current nonnegative request state through a native UpDownCounter by recording state deltas; all other gauges use native last-value instruments. The [distributed example](../../examples/distributed-tracing/README.md) exercises two isolated applications, real sockets, correlated logs and process-level diagnostics.
