# @arkenivajs/metering

`createMeter(options)` creates independent technical usage scopes with an owned event exporter. It requires immutable service metadata and a synchronous `auth.isVerifiedTenant` checker bound to the verifier that minted the tenant context. Clones, foreign contexts, revoked verification and asynchronous or failing provenance checks are rejected. No request header, TypeScript cast or serialized tenant object establishes trust. The meter never issues credentials or computes currency values.

`start({tenant,operation,requestId?})` returns a manual session without entering an asynchronous scope or performing I/O. `run(session,work)` enters an owned live session for adapter integrations; `measure(input,work)` starts a scope, awaits its callback and closes it on success, failure or cancellation. Concurrent scopes are isolated through AsyncLocalStorage. Child scopes retain the original request and trace identifiers and receive a unique operation identifier and parent link. A nested scope cannot change tenant or request correlation. Work continuing after a parent ends needs a new explicit scope; late implicit children are rejected.

`recordUsage(name,{unit,value,source})` accumulates finite nonnegative quantities in registered dimensions. `usageDefinitions` registers at most 128 names, including reserved framework dimensions. Names contain 2–80 lowercase letters, digits, underscores or periods and begin with a letter. Units are `bytes`, `operations`, `milliseconds` or `items`; source is `observed` or `derived`. A dimension cannot change unit or mix sources in one event. `recordOperation(name,count?)` records integer operation counts, default one; explicitly measured zero is permitted. Built-in names are `http.requests`, `http.response.bytes`, `db.query`, `db.client.elapsed`, `http.client.requests` and `http.client.response.bytes` with their corresponding units. An application must avoid counting an operation both manually and automatically.

`recordError(error)` records only a completion category. Raw messages, stacks, claims and submitted secrets never enter the event. `end(status?)` closes exactly once and returns an immutable enqueue receipt; it performs no file or network I/O. A manual scope with no outcome uses `unknown`; `measure` uses `ok`, `error` or `aborted`. Repeated completion and use of an ended or foreign session throw `EK_METER_SESSION`.

Events use protocol `1.0.0`, independent UUIDv4 event/operation identifiers, UTC timestamps and a monotonic elapsed duration in milliseconds. Service metadata and optional validated workload metadata are captured at construction. Optional trace correlation is independent of trace sampling and grants no authentication. Process CPU/RSS are separate process metrics, never exact tenant CPU or memory. Local scope wall durations may overlap; do not add parent and child durations as exclusive CPU.

Default bounds are 10,000 queued events, 16 MiB queued encoded data, 10,000 active sessions, 128 registered dimensions, 16 KiB per encoded event and 100 events per export batch. Queue bounds include an in-flight batch. Overflow returns `accepted:false` with `capacity`; oversized events return `invalid`; disabled export returns `disabled`. An active-session limit throws `EK_METER_CAPACITY` for manual start; `measure` still executes business work once in an isolated unmetered scope and records the loss. Diagnostic provider failures cannot retry business work or change its result.

The `MeterExporter` SPI owns an independent `jsonl` or `http` event transport. Its `export` promise resolves only when the entire immutable batch is acknowledged according to that transport's contract. It must honor cancellation and bounded deadlines. Transport ownership transfers to the meter; sharing the same owned exporter across meters is unsupported. OTLP spans are not an event transport. Event IDs remain identical on retry so an external consumer can deduplicate uncertain or repeated delivery.

Export runs asynchronously after enqueue and on an unreferenced periodic timer (default one second). Each attempt has a five-second default deadline, at most three attempts and a 100 ms retry delay. Nonretryable typed transport errors are not replayed. Every failed attempt increments `failedExports`; permanently unacknowledged accepted events increment `dropped`. `flush(options?)` waits within its caller deadline and never equates enqueue with delivery. Accepted-event loss remains a sticky `EK_METER_EXPORT` failure for the meter's lifetime, including after later recovery; service counters retain the evidence. Restarting a process does not recover its in-memory queue. This mode is best-effort.

`stats()` returns immutable enqueue/export/drop/failure counts and queue depth; `snapshot()` returns current active sessions, queue depth and drops. These are process-local counters, not durable historical or tenant-wide reports. Optional low-cardinality telemetry records event/queue diagnostics without tenant, event or trace labels. Accepted-event export failures must be joined with these diagnostics by an external consumer.

`markMissing(session,reason)` records stable coverage gaps. Completeness covers supported instrumented local work only. An unfinished child marks `downstream_unobserved`; a rejected child marks queue loss on its live parent; cancellation marks `aborted_before_close`. Already finalized events are immutable and cannot be retroactively repaired. An optional trace identifier being absent is not by itself a metering loss.

`close(options?)` rejects new sessions, closes remaining scopes as aborted, attempts bounded flush, cancels transport activity and closes the owned exporter once. It preserves a flush failure while still attempting exporter cleanup. Importing the package creates no timer or connection. There is no default in-memory production exporter or implicit production accounting backend.

`parseMeteringEvent(value)` validates and freezes this producer's wire envelope before transport, rejecting extra fields, malformed dates, invalid quantities and inconsistent completeness. Every exporter applies it to each incoming event. The event schema and transport version remain `1.0.0` when package versions change.

`await createJsonlExporter({workspace,path,maxFileBytes?,retainedFiles?,rotationIntervalMs?})` opens a dedicated POSIX file and exclusive `.lock` with mode `0600`. The workspace and existing parent directories must be owned by the current user and not writable by group/others. The path is relative to that workspace; directory links, final symlinks, hard links, public files and incomplete existing record suffixes are rejected. Concurrent owners fail rather than sharing append or stealing a stale lock. Do not modify a live writer's files or remove its lock; after a crash, an operator must establish that the original owner cannot still write before recovering the file/lock.

The JSONL writer acknowledges only complete batches after file synchronization. Rotation synchronizes files and directory entries, keeps the active file plus five retained files by default, rotates at 10 MiB or 24 hours and resumes the age of an existing file after restart. Oldest retained files are removed under the same exclusive ownership. A partial write attempts truncation to the last complete boundary; any uncertain file failure poisons the writer until it is closed and recovered. Cancellation/deadline does not acknowledge an unconfirmed write. Event IDs support consumer deduplication if a completed but unacknowledged write is retried.

`createHttpMeterExporter({endpoint,authorization,environment?,allowInsecureLoopback?,allowPrivateNetwork?})` owns a separate bounded client. `endpoint` is one trusted origin; requests always target `POST /v1/metering/events` with JSON `{schemaVersion,events}` and `X-ArkenivaJS-Metering-Version: 1.0.0`. The synchronous/asynchronous authorization callback supplies a collector-specific bearer credential; credentials never enter event records. Production requires HTTPS with CA/hostname validation. Private destinations require explicit deployment policy. Plain loopback HTTP is allowed only with an explicit development/test exception. No redirect or automatic business request retry is enabled.

Only `202` acknowledges an entire HTTP batch according to the external collector's durable acceptance contract. The framework cannot prove arbitrary server durability from a status alone. Other success codes and authorization failures are rejected; `429` and server failures are retryable under the meter's bounded retry policy. One connection, a 64 KiB response bound and a shared authorization/request deadline limit resources. Closing aborts pending exporter activity and releases the client. An independently secured, deduplicating collector and its retention policy remain application infrastructure.

The mandatory `pnpm test:integration:metering` suite requires `ARKENIVAJS_METER_INTEGRATION_ENDPOINT`, `ARKENIVAJS_METER_COLLECTOR_AUTHORIZATION` and an external `ARKENIVAJS_METER_EVIDENCE_PATH`. Missing infrastructure fails. The disposable Python collector fixture requires `--test-only`, writes private JSONL records, deduplicates event IDs and fsyncs before returning `202`. It is test infrastructure, not a production collector. Run it inside a disposable VM/container when testing on a development laptop; the CI job uses its disposable runner. After the suite, `node scripts/check-meter-collector.mjs EVIDENCE_JSON DURABLE_JSONL` independently checks persisted records, both tenants and duplicate suppression. Stop the fixture and retain only protected external evidence.
