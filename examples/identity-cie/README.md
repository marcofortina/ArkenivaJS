# CIE OIDC application and browser transaction example

Run `pnpm --filter @arkenivajs/example-identity-cie build` and `pnpm --filter @arkenivajs/example-identity-cie test` from the workspace root. `node scripts/check-packed-examples.mjs --example identity-cie` installs actual package archives into an independent consumer, then compiles and executes this example there.

The application explicitly installs public logging, security, Crypto and `ciePlugin` APIs. Its CIE profiles use pinned federation anchors, mandatory live RP/OP participation checks, explicit endpoint permissions, native JOSE/OpenID Client, JAR, PKCE and private-key JWT. The HTTPS fixture returns signed and encrypted ID Tokens and UserInfo, with encryption explicitly registered. Standard wire assurance identifiers map to `cie-l2` only after protocol and trust verification. The application's actual AuthService verifies the approved canonical subject and tenant; a constructed context or callback attribute grants no authority.

`src/browser-flow.ts` wraps a server-selected public `CieService.forProfile(profileId)` view. Apply the status, headers and empty body returned by `beginBrowserLogin`. Its first-party `__Host-cie-flow` cookie binds the service-issued state, uses `Secure`, `HttpOnly`, `Path=/` and `SameSite=Lax`, and expires after the shorter of five minutes and the protected transaction lifetime. It is distinct from the SPID browser cookie. This example supports one active CIE ceremony per browser at a time. Responses disable caching and referrers.

For the registered top-level GET callback, construct the absolute URL from the application's fixed configured HTTPS origin. Set `clearBrowserCookie` before calling `consumeBrowserLogin`, including error responses. Pass the incoming Cookie header, callback URL and exact configured callback URI. Missing, foreign, duplicate or malformed cookie/state values and changed callback origins, paths or fixed query parameters are rejected before federation work. A SPID cookie cannot substitute for the CIE cookie. The service separately validates current trust, issuer, assurance, nonce, PKCE, response signatures, encryption and shared atomic one-use state. The cookie is a browser binding, not an identity or application session.

Tests execute real HTTPS begin and callback requests, reject a foreign cookie without token exchange, accept the canonical identity once and reject replay. They also exercise explicit profile/provider selection, readiness, unavailable storage, revoked trust, changed keys, concurrent consumption and actual standard/detailed telemetry exports. Authentication duration counts public attempts once; check/failure metrics and logs contain only closed operation/outcome categories. No tenant, subject, endpoint, key reference or protocol material is exported. These are native protocol fixtures; they do not establish official interoperability or accreditation.

The fixture's ephemeral CA, keys, canonical accounts, federation and in-memory transactional store are test-only. TLS trust is scoped to the child process; verification remains enabled. All owned listeners, collectors and temporary material are retired after tests. Production and development require approved external keys, durable shared one-use storage, administrative RP registration, current pinned trust material, a configured federation resolver and an independently accepted deployment. The example does not host a federation resolver or create a local session or MFA factor. Apply local authorization and session policy explicitly after receiving the canonical identity.

SAML is unavailable in this adapter. Official conformance, release acceptance and deferred performance/duration campaigns remain separate gates. See the [CIE package guide](../../packages/identity-cie/README.md).
